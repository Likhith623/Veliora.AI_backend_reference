## Documentation
Issue: Auto-Deployment Failing due to Expiring SSH Keys
Background
We have a GitHub Actions workflow that automatically deploys the latest code to our VM (novi-backend) whenever there is a push to the main branch.
This workflow relies on SSH access from GitHub Actions to the VM using a private/public key pair.
Problem
Initially, the SSH keys were auto-generated by Google OS Login when we connected to the VM.
These keys had an expiry time (in metadata: "expireOn": "...") — usually valid for only a few minutes or hours.
After expiry, auto-deployment started failing with this error:

Permission denied (publickey).
Error: Process completed with exit code 255.


Manually reconnecting from a local terminal worked temporarily, but the problem returned because the OS Login-generated keys kept getting replaced.

Root Cause
Google OS Login was enabled for the VM, which means:

Every login via gcloud or Google Console injects a new temporary SSH key into ~/.ssh/authorized_keys.

These keys are tied to your Google account session and expire automatically.

Any manually added keys get overridden or ignored.

Solution: Permanent SSH Key for GitHub Deployment
Step 1: Generate a Permanent Key Pair

Run on your local machine (Mac/Linux):

ssh-keygen -t ed25519 -C "github-deploy@novi-backend" -f ~/.ssh/github_deploy_key


This creates:

Private key: ~/.ssh/github_deploy_key

Public key: ~/.ssh/github_deploy_key.pub

Leave passphrase empty for automation.

Step 2: Add the Public Key to VM

On the VM:

mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "ssh-ed25519 AAAAC3...your-public-key... github-deploy@novi-backend" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

Step 3: Disable Google OS Login for the VM

On your local machine with gcloud CLI:

gcloud compute instances remove-metadata novi-backend \
  --zone=asia-south1-c \
  --keys=enable-oslogin


This prevents Google from injecting expiring keys into the VM.

Step 4: Disable PAM Authentication for SSH

On the VM:

sudo bash -c 'echo "UsePAM no" >> /etc/ssh/sshd_config'
sudo systemctl restart ssh


This ensures SSH uses only the keys in ~/.ssh/authorized_keys.

Step 5: Add Private Key to GitHub Actions Secrets

In your GitHub repo settings → Secrets and variables → Actions:

Add a secret named SSH_PRIVATE_KEY
Paste the content of your local ~/.ssh/github_deploy_key.

Step 6: Update GitHub Actions Workflow

In .github/workflows/deploy.yml:

- name: Setup SSH
  uses: webfactory/ssh-agent@v0.5.4
  with:
    ssh-private-key: ${{ secrets.SSH_PRIVATE_KEY }}

- name: Test SSH Connection
  run: ssh -o StrictHostKeyChecking=no user@host "echo '✅ SSH connection successful'"

Outcome

Permanent SSH key is now fully under our control.

No more auto-expiry issues.

GitHub Actions can now deploy without interruption.

Why So Many Key Changes?

We initially tried using Google OS Login’s keys, but they kept expiring.
Then we added a manual key, but it was still overridden by OS Login.
The final fix was:

Generate our own permanent key.

Add it manually to authorized_keys.

Disable Google OS Login so nothing overwrites it.

Configure GitHub Actions to use that permanent key.
